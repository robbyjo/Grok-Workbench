# Desktop workflows in 0.9.0

Open **Desktop & read aloud → Office, shopping, art, science & chess → Documents, browser & desktop workflows** in a project chat. Enable the workflows needed for that chat, select a starter and describe the task. Office/JMP/Blender/Krita also require their application grants in the parent panel. The embedded engine remains **Grok Build 1.0.45**, source `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`, binding 0.6.0.

Grants are off by default and reset on disconnect, archive/hide, engine change, remote-access start and application restart. They authorize the stated application operations; they are not OS containment. Files, screenshots and results requested by a tool become context for the selected model. Stop cancels pending work; an already delivered native operation may still finish. Inspect uncertain outcomes before retrying.

## Workflows and limits

| Workflow               | What it does                                                                                                                                                                                                                                               | Requirements and scope                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Office editing         | `office_edit` revises a new DOCX/XLSX/PPTX copy. Word supports literal replacements, anchored comments, append and tracked changes. Excel changes typed cells/formulas and recalculates. PowerPoint creates/appends slides and exports PDF.                | Windows Microsoft Office in the standard Office16 install path. Originals stay unchanged. Macro/embedded/external relationships are rejected, including linked documents that require manual handling. Word anchors/replacements use literal text, without caret codes.                                                                                                                                                                               |
| PDF and OCR            | `document_workflow` inspects/fills forms, merges, splits/selects pages, draws visible highlights/text, extracts text/layout tables, and recognizes scanned PDFs/PNG/JPEG.                                                                                  | PDF modifications use pdf-lib; extraction/rasterization uses bundled PDF.js. Offline OCR uses Windows OCR, installed recognition languages and the bundled PowerShell helper under the machine's existing script policy. No OCR language/model downloads occur automatically. Other PDF operations work across platforms.                                                                                                                             |
| Scientific reporting   | `report_create` imports numeric CSV/XLSX columns → native JMP scatterplot/OLS → independently checked estimates → residual CSV/native plot → illustrated Word report, optional Excel chart and PowerPoint/PDF.                                             | Windows JMP 16 and Office grants. At most 5,000 numeric pairs (2,000 with workbook export). Missing/nonnumeric rows are refused, not silently dropped. XLSX formula cells require a values-only export to avoid stale cached results. Numerical checks do not establish statistical assumptions, significance or causation.                                                                                                                           |
| File organization      | `file_organize` previews literal rename/prefix and extension-folder organization; reports SHA-256 duplicates. The panel applies or undoes the exact reviewed plan.                                                                                         | Ordinary workspace files only, 200 files / 128 MiB per plan. Private folders, links and overwrites are excluded. Duplicates are never deleted. Source changes invalidate the plan. A JSON journal records completed moves for later review/undo; a crash inside an individual filesystem operation may require manual reconciliation.                                                                                                                 |
| Browser administration | `browser_view` observes visible text, controls, forms and a screenshot in a separate ephemeral task browser. `browser_act` fills/selects/checks, follows links, downloads reports, and prepares form submission for review.                                | Open the browser from the panel first. Each model action needs a fresh view, valid for 30 seconds and one action. Human submission review is bound to the unchanged form/target. Popup windows and unapproved non-read requests are blocked. Password/file fields, cross-origin frames and complex authenticated/SPAs need manual handling or the separately granted desktop window bridge.                                                           |
| Creative batches       | `creative_batch` renders up to six Blender scene variants, exports up to four chat-owned Krita documents, or runs an explicitly approved local ComfyUI API workflow and copies its images.                                                                 | Relevant application grants and working installed applications/servers. Use `scenes` for Blender and `overrides[].changes` for ComfyUI. Comfy approval binds the file's SHA-256 and local origin; the wrapper supports listed built-in local image nodes, dimensions up to 2048, batches up to four, and sampling up to 40 steps. Custom/partner API graphs are outside this adapter. It never clears or interrupts a shared queue.                   |
| Research libraries     | `research_library` imports CSL JSON/RIS, exports interchange files, plain author/year bibliography, cited notes and optional Word report. `zotero_read` reads local items/annotations. A separate reviewed action creates a new Zotero collection/records. | Reference IDs/page labels must be supplied for notes; missing authors/dates remain explicit. Bibliography formatting is a plain listing, not a complete CSL style engine. Source quotations/metadata require verification. Zotero local API must already be enabled; writes require Zotero's own local authorization and Workbench's concrete review, up to 50 new records. No existing records are edited.                                           |
| Audio editing          | `audio_edit` trims, concatenates and optionally peak-normalizes segments, exporting new 16-bit PCM WAV plus an Audacity import macro. Optional Audacity scripting uses its installed Windows pipe module.                                                  | Inputs need matching rates/channels, mono/stereo. PCM WAV: 16-bit, 8–192 kHz. Other formats use available Chromium decoders; decoding resamples to the AudioContext rate and is limited to 16 MiB PCM. Final PCM output is capped at 40 MiB. Native Audacity needs a functioning active project and mod-script-pipe (3.x; newer versions may lack it); the project stays open for review. No transcription, denoising or music generation is implied. |
| Vector graphics        | `vector_graphic` creates basic editable SVG shapes/text/paths, edits a new SVG copy by ID, and exports up to eight PNG sizes and optional PDF.                                                                                                             | Shapes use `kind` (`rect`, `circle`, `text`, etc.), not `type`. Scripts/external resources and unsupported SVG elements/styles are refused. Built-in PDF contains a raster preview. Choose the installed Inkscape executable in the panel and `backend=inkscape` for native PNG/vector-PDF exports. Arbitrary Inkscape effects are unvalidated.                                                                                                       |

Use `workflow_status` to inspect actual outcomes, optionally with `wait_ms=10000` during a job. Use `workflow_artifact` to inspect this chat's registered PNG/text/CSV/JSON/SVG/RIS outputs. Jobs are asynchronous, single active at a time, with a ten-minute overall deadline; native subprocesses have shorter deadlines. New artifacts use unique project `workbench-output` directories. They are retained on completion/failure. Runtime job/review records reset on restart; the files remain. Application tool status uses the separate `application_jobs` tool.

PDF bounds: 20 MiB per source, at most ten merge sources, 100 pages per input / 200 merged pages; text extraction up to 100 pages / 120,000 characters, raster/OCR up to ten pages per request. PDF form `fields` is an array such as `[{"name":"reviewer","value":"Alex"}]` or `[{"name":"approved","checked":true}]`. Annotation coordinates are PDF points from bottom-left. Overlays are not redaction. Layout-derived CSV columns and OCR words require review before scientific use; source hashes and page numbers are retained. Password-protected PDFs require an unlocked copy.

The task browser has its own session, without cookies from the user's regular browser or a Workbench preload. Downloads are limited to 20 files, 20 MiB each, under a new output directory; executable/script downloads are refused and files are never automatically run. Use the dedicated `download` action for a report link, rather than navigating to a download response. The session is discarded on close/revocation. A reviewed form request is not proof of server acceptance: inspect the resulting page. These controls are not a universal payment or website-side-effect interceptor.

File-plan review checks owner, plan hash, content and source identity, refuses existing destinations, and stops remaining moves when permission changes. Undo refuses changed outputs or occupied original paths. After restart, `file_organize` with `action=restore` and the journal's workspace path reloads a plan for a new explicit review. It does not execute automatically. Empty directories created during organization may remain after undo.

The local Zotero adapter uses `http://127.0.0.1:23119/api/`, API version 3 and the returned server identity. Local write keys remain in memory, scoped to the chat, and never appear in model status. A single-use Zotero grant may cover only one write; if collection creation succeeds but record creation needs reauthorization, the plan shows partial and requires review again. A timeout is an uncertain write, not permission to duplicate it. CSL/RIS export remains available without Zotero installed. No Zotero configuration, personal library or native allowed root is silently changed.

Audacity exports use the active project's sample rate, which can differ from the built-in `edited.wav` preview. Follow-up source after v0.9.0 reports the actual native export's rate, duration, channels and measured peak, with preview details under `sourcePreview`. The published v0.9.0 summary reports the preview rate even when Audacity resamples; inspect the exported WAV header for its actual format. A visible dedicated empty Audacity 3.7.9 project passed native import/normalization/export testing; the adapter remains experimental.

## Examples

- “Revise a copy of `draft.docx`, replace ‘provisional’ with ‘approved’, track the change and comment on the conclusion.”
- “Read the scan in `paper.pdf` through OCR, inspect the text, then read the generated TXT aloud.”
- “Analyze `experiment.csv`, columns Dose and Response, in JMP and produce a Word report with fit/residual plots plus slides.”
- “Preview organizing these files into extension folders with prefix `2026-`; wait for my review.”
- “Prepare the report-request form in the task browser and show me its submission review.”
- “Render these Blender variants and inspect each output.”
- “Import `papers.ris`, retain their metadata and create cited notes from the supplied annotations.”
- “Join these narration segments, trim the first half-second and normalize to −3 dBFS.”
- “Create an editable SVG flowchart and export 800×600 and 1600×1200 PNGs.”

## Verification

```powershell
npm run test:desktop-workflows
npm run test:desktop-workflows:live -- --home 'ABSOLUTE\AUTHENTICATED\GROK\PROFILE'
npx tsx scripts/desktop-workflows-acceptance.ts --domains browser
npx tsx scripts/desktop-workflows-acceptance.ts --domains vector --inkscape 'ABSOLUTE\inkscape.exe'
```

Native application tests require those installed applications. Live tests use billable Grok requests, an isolated profile/auth copy and synthetic data, then remove the temporary Grok home. Tests never place orders, send real messages, join rated games, or modify a personal research library. [Validation evidence](VALIDATION.md) distinguishes live application, model, protocol-fixture and untested coverage. Linux remains experimental; macOS desktop behavior remains UNTESTED pending volunteer validation.
