# Release gates and CI publication

The published release is **v0.8.5 alpha**, accepted by [Windows](https://github.com/robbyjo/Grok-Workbench/actions/runs/41274679777), [Linux](https://github.com/robbyjo/Grok-Workbench/actions/runs/41274679751) and [both Mac architectures](https://github.com/robbyjo/Grok-Workbench/actions/runs/41274680825) at source `626a93a30818d1c66d8a65ee9a95375d44a32ca7` and published by the [verified-artifact workflow](https://github.com/robbyjo/Grok-Workbench/actions/runs/41277647210). Windows is unsigned, Linux is experimental and both macOS architectures are UNTESTED until volunteer desktop validation. All 18 public downloads matched their recorded sizes/digests; all five packages matched their sidecars/provenance, with Linux/Mac engine CPU/hash checks. GitHub Latest resolves to v0.8.5. Existing v0.8.4 tag and asset identities remain unchanged. Do not replace published release assets or tags. See [the publication record](VALIDATION.md) for hashes, acceptance and remaining external gates.

`.github/workflows/windows.yml` checks formatting/types and focused desktop regressions before building the pinned public native source on GitHub-hosted Windows, then runs backend and source/packaged GUI acceptance and tests portable relocation and replacement/rollback. A source/toolchain/image-keyed Cargo cache retains successful native compilation before later checks. Upload names include the exact source SHA. Windows TEMP aliases are handled consistently by Git ancestry, file listings and saved project identity.

For a later release, run **Publish tested platform release** manually from the same main commit accepted by Windows, Linux and both Mac builds. Enter all three workflow run IDs and choose the signed Windows artifact only after signing enrollment. Mac runs may use the `codex/linux-macos-builds` cache branch only when its source SHA exactly matches main. The workflow rejects failed, running, stale, PR/fork and unrelated workflows, checks PE identity and Linux/Mac engine CPU/checksums, refuses existing tags, creates a draft, verifies every GitHub asset digest, then publishes those exact artifacts as an alpha. It never rebuilds for publication. Configure the GitHub `releases` environment with the desired human reviewer protection. No new release is authorized or published by merely implementing these source changes.

SignPath is disabled unless `SIGNPATH_ENABLED=true` and the approved account, MFA, policy, artifact restrictions, protected `code-signing` environment and submitter secret are configured. Actual Foundation approval, human signing, certificate trust, and a published signed newer-version update remain open.

External gates still open: a pristine dependency-free Windows machine, physical reboot persistence and forced real token expiry/refresh; real client-managed HTTP MCP OAuth sign-in/expiry/logout/reconnect; live Windows Sandbox containment; in-process agent AppContainer/broker integration; unavailable real API-key provider acceptance; full screen-reader QA. Existing Windows laptop fresh OAuth/model request/restart/session resume and real native/provider tests are documented in [VALIDATION.md](VALIDATION.md); they do not complete these distinct gates.

For HTTP MCP OAuth, [Linear’s official server](https://linear.app/docs/mcp) supports Streamable HTTP and OAuth 2.1 dynamic registration. Start with `https://mcp.linear.app/mcp/readonly`, a Linear account/workspace and human browser consent. Connect directly as HTTP in Workbench; a STDIO `mcp-remote` wrapper or API key would not test the required client-managed HTTP flow. Provider expiry/revocation/logout and reconnect must be exercised separately. No provider has been connected automatically for this recommendation.

Windows containment testing needs a machine with hardware virtualization and Windows Sandbox enabled on a supported Pro/Enterprise/Education edition ([Microsoft requirements](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)). Feature enablement may require administrator access and reboot; GPU must not reboot during the ongoing experiment. The existing optional whole-app guest launcher needs real tool/hook/terminal/descendant escape and network tests. Integrating containment into normal agent execution additionally requires a native broker enforcing file/process/network access for every tool and descendant, plus explicit reviewed recovery/apply. Ordinary Windows launches still have host-user permissions.
