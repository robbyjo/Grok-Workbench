# Grok Workbench 0.8.4 (alpha)

Windows 10/11 x64 portable. Unsigned; Windows may show SmartScreen warnings.

- **Structured Grok questions:** selectable choices, multiple selections when requested, option descriptions/previews, free-text answers, explicit submission and cancellation. Questions are bound to their native session and request, remain available after renderer reload, and close on tool completion, cancellation or disconnect. Notifications and sidebar markers identify chats needing input. The engine's existing question feature/account gates still apply.
- **Automatic workspace refresh:** a debounced recursive watcher refreshes the visible workspace's file list, saved editor contents and Git Changes after external/tool edits. Focus also reconciles the editor and Git view. Dirty drafts are retained; a comparison shows the last saved text, current disk text and your draft. Keyboard saves use the immediate editor text, and stale disk-read replies cannot replace a newly saved buffer. Atomic saves retry brief Windows replacement locks with less than one second of retry delays, rechecking paths, read-only status and disk content on every attempt. Persistent locks fail with the draft retained. Existing stale-save and path checks remain enforced. Generated dependency/build directories are excluded from watch notifications; this is not a filesystem lock.
- **Changes from this turn:** expand a completed/stopped/failed turn to review its reported successful file edits, with Before/After text. Exact consecutive edit versions for a path combine; discontinuous versions remain separate. Review reads the durable transcript even when the visible history page shortened a large tool entry. Shell commands and external writers may make additional changes: repository Changes remains necessary. Review is bounded to 100 edit records with a bounded text budget and a 4 MiB/1,000-entry turn scan; truncation is shown. No automatic undo/apply is introduced.
- **Persistent unread results:** new terminal results mark chats unread, retaining the first unseen result across restart. Mark read/unread and First unread result controls are available above the chat. Marking a chat read uses the displayed receipt revision and refuses an outdated receipt if another result arrived. Reading is explicit; simply loading a chat does not acknowledge its results. Conversation rewind clears obsolete receipts.
- **Screenshot paste and file drops:** paste a screenshot with Ctrl+V in the message box, or drop files onto the composer. Imports reuse owned durable assets, the five-files-per-prompt limit, 50 MiB/file limit, storage admission checks, previews and draft recovery. Clipboard images are limited to 40 megapixels. Files stay local until a prompt is sent; model interpretation still depends on its supported tools.

Validation includes protocol-fixture question round trips, real Windows filesystem notifications, stale acknowledgement rejection, edit-chain/external-writer isolation and source/packaged desktop acceptance. The new desktop scenario exercises native clipboard paste, an OS-backed File drop, editor conflict preservation, automatic Git refresh, restart persistence and the question UI through the actual process/IPC path with a deterministic engine fixture. This does not establish new live model/provider acceptance or physical Explorer drag-and-drop testing.

Close Workbench before a manual upgrade, replace the executable and retain the adjacent **Grok Desktop Data** folder. Existing profiles receive optional read-state metadata; the desktop/history schemas, binding ABI and pinned native storage contract are unchanged. Upgrades from 0.7.0 or earlier require manual executable replacement. Publication uses only the exact successful Windows CI artifact after backend, source/packaged desktop, portable relocation and replacement/restart/rollback acceptance. See [remaining gates](RELEASE-GATES.md).
